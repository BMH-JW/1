# 彼方委托所 策划答复测试版使用说明

适用对象：数据配置、界面接入、程序调试和测试同学。Unity版本为 **2022.3.62f3c1**。

本轮依据《程序问题逐项答复与完整规则配置稿 信任值暂定测试版》，以及用户于2026年10月18日授权采用的分析建议更新。默认资产现在可以直接开始**测试局**，不再要求填调查额度或启用F003。测试参数、样本人物、占位立绘和事实反馈均有明确标记，不代表最终平衡或正式叙事。

修改范围为 `Assets/GameData`。原房间、主菜单、剧情场景、旧UI及其事件绑定未改动；正式场景仍需队友接入。此前交给策划的Word属于沟通历史，本轮执行口径以本说明和当前配置为准。

## 1 首次使用

1. 打开Unity，等待脚本编译和资产导入完成。
2. 打开 **Tools → JU → Game Data → 数据调试窗口**。
3. 默认选择 `DefaultGameDataConfig`，种子保持42，点击 **检查运行条件**。预期通过。
4. 点击 **开始测试局**，在“当日规则”页阅读本日公告。
5. 打开“申请者/审批”，阅读通关文书、羁绊牵挂、驱力等级。玩家只能按申报放行或拒签。
6. 打开“记录/日结”，查看记账结果，点击 **结算当前日并进入次日**。
7. 查看两界与信任的实际变化，再到“次日反馈”模拟播放完成并消费反馈。
8. 到“多日模拟”，用同一种子比较三种策略，各模拟30天并导出CSV，供策划检查数值。

不需要点击Play。调试窗口的操作不修改资产和场景。同一天反复打开界面不会重新抽人数、人物或属性。关闭窗口、重新编译或重启Unity后内存局丢失；没有跨进程存档功能。

## 2 本轮采用的规则

| 项目 | 当前执行 |
|---|---|
| 世界 | Utopia=灵虚，AntiUtopia=废墟；内部编号不变 |
| 每日人数 | 在配置上下限内等概率取整数，默认4～8，每天一次 |
| 来源世界 | 每人独立等概率抽取，不保证当天两界人数均分，不设人数配额 |
| 申报目的地 | 必须是来源世界的另一界 |
| 初始值与范围 | 两界及信任初始均50，范围0～100 |
| 准入依据 | 仅记忆：1～2级去废墟，3～5级去灵虚；原始值0属于3级 |
| 合规操作 | 申报与记忆目标相同时按申报放行；不同时拒签。不得改派另一界 |
| 身体状态 | 真实身体按欲望等级查表；不参与准入 |
| 申报类型与真实动机 | 由人物样本明确指定，不执行F003，不自动挑选极端动机 |
| 放行世界影响 | 灵虚变化=M/5；废墟变化=−M/5；M为审批时记忆原始值 |
| 拒签世界影响 | 来源世界−1，另一世界不变；拒签不改记忆，不进入收容 |
| 信任测试规则 | 合规处理+3，违规处理−5，含放行和拒签；取消每日固定+5 |
| 结算 | 审批只记账；日终累计两界影响，对旧值加总变化统一四舍五入，再限幅 |
| 即时反馈 | 默认只显示“处理已记录”；不提前透露合规答案 |
| 次日反馈 | 日结成功后入队，默认次日可读；播放完成后确认消费 |

上述信任和世界公式是**当前可执行的测试标准**。`confirmed`表示获准用于当前测试，`testOnly`仍说明未完成最终平衡确认。

### 几个容易误解的地方

- **记忆等级不等于残留程度。** 等级1～5对应残留分值5～1；中间分值3明确归灵虚，不再拒签。
- **拒签不等于扣留。** 本版拒签结束当次申请；扣留接口会明确拒绝执行，没有隐藏的收容或扣费效果。
- **合规和后果分开记录。** 按当前公式，合规放行影响非负；合规拒签仍会降低来源世界。不能用世界影响正负判断合规。
- **“实时显示”指刷新实际状态。** 审批阶段状态未变；日结后UI立即刷新实际值。若显示预测，必须单独标为待结算，不能写入真实状态。
- **未处理申请者**次日离开，不自动拒签、不产生拒签扣除、不计入信任奖惩。

## 3 调试窗口六个页面

| 页面 | 作用 |
|---|---|
| 配置检查 | 查看来源文件、实现约定、待完善事项、公式启停；复制错误信息 |
| 当日规则 | 查看和后台判定同源的通讯机公告 |
| 申请者/审批 | 筛选今日申请，查看玩家文书与两条档案，按申报放行或拒签 |
| 记录/日结 | 核对合规与两界待结算影响，推进一天，复制报告，检查重复日结拦截 |
| 次日反馈 | 查看等待、可播放、已消费事件，模拟播放完成 |
| 多日模拟 | 在独立局中比较按规则、全部放行、全部拒签三种策略，导出CSV |

“申请者/审批”页的 **开发者检查** 默认折叠，包含真实属性、身份ID、立绘Key、样本申报类型、隐藏动机和规则答案。它用于调试，不是玩家调查功能，不需要调查额度。

如果立绘未绑定，会显示明确提示，不会偷偷换成其他图片。默认配置使用带 `sample:` 前缀的占位Key，可以验证跨日一致性，但不会凭空生成正式角色图片。

### 多日模拟如何比较

三种策略分别新建一局，使用同一配置快照和种子，不推进当前调试局；人数与申请者序列保持一致。每个日结记录人数、放行/拒签数、合规数、信任、两界状态、原始累计变化、实际净变化和触边情况。

CSV中的策略：FollowRules=按规则，AlwaysRelease=全部放行，AlwaysReject=全部拒签。文件带UTF-8 BOM，方便用Excel打开。

不要仅看最终值。还要看信任是否很快触顶/触底、两界何时到0/100，以及全部拒签是否有过强影响。触边不是当前失败条件，模拟会继续记录。

## 4 修改配置

建议在Project中选中默认资产，按 **Ctrl+D** 做自己的副本。菜单 **创建当前测试基线副本** 则使用 `Defaults.json` 重建当前基线，不保留你对另一个资产的调整。

Inspector按版本、每日流程、准入规则、人物身份、生成数据、测试结算、机制开关、反馈及日志分组。修改后先检查运行条件，再重新开局；当前局使用独立快照，不跟随Inspector变化。

### 重点字段

| 字段 | 含义 |
|---|---|
| `testConfiguration` | 当前是否为测试配置；不能为了发布直接取消它而忽略测试公式与占位资料 |
| `minDailyApplicants/maxDailyApplicants` | 每日人数上下限，默认4和8 |
| `impactDivisor` | 记忆世界公式除数，测试值5 |
| `rejectionSourcePenalty` | 拒签来源扣除，默认1 |
| `complianceReward/violationPenalty` | 全部合规/违规处理的信任奖惩，测试3和5 |
| `showImmediateCompliance` | 是否在即时提示展示合规结果；默认关闭 |
| `identities` | 稳定人物身份、姓名、原籍、可选固定立绘、申报类型和动机 |
| `portraitPools` | 原籍对应的立绘Key列表 |
| `portraitBindings` | 根配置上的Key到Unity Sprite绑定，独立于纯数据 |
| `implementationDecisions` | 本轮已经采用的实现约定，不再列为旧待确认事项 |
| `pendingDecisions` | 仍需完善的内容，如正式叙事、最终平衡和事件条件 |

表1负责数值到等级；表6负责每项属性独立抽样的等级权重，再在该等级区间内取整数。基础权重保持15%、35%、5%、35%、10%，没有因为记忆3级已归灵虚就擅自降低它的概率。

### 人物身份与跨日复现

人物身份和申请实例分别有ID。例如 `PERSON-001` 是同一个人，今天的 `NPC-000001` 与明天的 `NPC-000009` 是不同申请。每局开始时会为人物按原籍池确定一次立绘，之后同一人物跨日保持姓名、原籍、立绘一致。

人物字段：

- `id/name/origin`：稳定身份、姓名、具体地区；全表不允许重复姓名，以保证单日不重复。
- `portraitKey`：可以明确指定池中的一个Key；留空表示本局开始时从原籍池选一次。
- `declarationType`：0诚实、1粉饰、2欺骗。F003关闭后必须明确给出，不按属性重算。
- `motiveId`：明确指定真实动机，用于特殊文书；不根据极端属性临时争抢优先级。
- `useFixedAttributes/fixedAttributes`：可做明确边界测试。默认关闭，四属性仍按表6随机；固定属性开启后必须位于−10～10。
- `sampleOnly/source`：是否为测试样本及来源说明。默认8人来自既有姓名原籍，类型轮换、动机暂用普通生活，均不是新增的正式角色设定。

正式内容需要审核“诚实文案是否符合该样本真实情况”。本版没有自动把文案语气或类型变成合规答案。其他属性跨日可变化，姓名、原籍和立绘不变。

### 美术立绘如何接入

1. 在 `portraitPools` 中填写原籍及可用Key，例如 `region7_person_a`。
2. 如需固定某个人的立绘，在该人物的 `portraitKey` 填入池中的Key。
3. 在资产根部的 **立绘Key到Sprite绑定** 新增同名Key，拖入实际Sprite。
4. 不允许同Key重复绑定。缺失、重复或图片为空都会明确报错，不随机兜底。
5. 场景通过 `GetPortraitKey(applicationId)` 取Key，再调用资产的 `ResolvePortrait(key)` 获取图片。

原籍只在普通通关文书中展示。普通人物档案接口不返回原籍、隐藏动机或真实数值；开发接口仍保留这些数据用于核验。

### 文书和反馈

保留原表11条模板，加上策划回复中的6条正式通用入境理由。匹配具体动机优先，再优先具体目的地，同级按ID升序。完整匹配键重复会报错；无覆盖不能开局，不临时编写默认文案。

文书占位符支持 `{name}/{origin}/{motive}/{motive_desc}/{destination}/{utopia}/{anti_utopia}`。诚实身体从欲望等级查真实明细，不显示“真实呈现当前状态”占位字样。原籍不再按旧伪装算法随机换成另一地区。

反馈模板按审批操作和可选合规条件匹配：`compliance=-1`不限、0违规、1合规；具体合规条件优先，同级按ID。每类审批必须有一条不限合规的模板。反馈占位符支持 `{day}/{name}/{choice}/{source}/{destination}/{purityDelta}/{orderDelta}/{actualPurityDelta}/{actualOrderDelta}/{utopia}/{anti_utopia}`。

`purityDelta/orderDelta`是该次记账影响；`actualPurityDelta/actualOrderDelta`是整天取整限幅后的实际净变化，不能混为同一个数。当前反馈有“调试事实”标记，正式新闻、传闻及个体后果仍待策划提供。

## 5 本版不执行什么

F003、F006～F012、F014、F015均不能在本版启用，检查会拦截。没有调查、扣留、收容、自然恢复、变异、道具效果、黑天鹅、每日固定信任或隐式失败。

45/55与40/60仅作为阈值资料保留。事件跨越方向、重复触发、冷却、持续天数及具体效果尚未完整定义，`enableThresholdEvents`不能开启。“低于40、某等级权重×2”的对应等级仍不明确，`enablePopulationFeedback`也不能开启。

测试运行检查不再用这些未定功能阻止基础流程；正式交付检查会提示测试公式、样本人物、占位立绘和调试反馈仍未转正。**运行检查通过不等于正式发布确认。**

## 6 场景接入示例

由一个控制器持有一个GameSession，不要每次打开面板重新开局。

```csharp
using JU.GameData;
using UnityEngine;

public class DataBridgeExample : MonoBehaviour
{
    public GameDataConfig config;
    private GameSession session;

    void Start()
    {
        session = GameSession.StartNewGame(config.data, 42);
        session.Diagnostic += message => Debug.Log(message);
        // 通讯机读取 session.GetRuleAnnouncement()。
    }

    public void HandleApplication(string applicationId, bool approve)
    {
        // approve=true表示按原申报目的地放行；false表示拒签。
        var result = session.SubmitApplication(applicationId, approve);
        if (!result.success) { Debug.LogError(result.error); return; }
        // 展示result.immediateFeedback；不要在这里再修改世界值或信任。
    }

    public void CloseDay(int expectedDay)
    {
        var report = session.EndDay(expectedDay);
        if (!report.success) { Debug.LogError(report.error); return; }
        // 用report.after刷新状态；读取GetAvailableFeedback，播放结束后ConsumeFeedback。
    }
}
```

| 接口 | 用途 |
|---|---|
| `GetState()` | 本局天数、当日生成数量、申请者、稳定身份、审批与反馈快照 |
| `GetRuleAnnouncement()` | 通讯机公告 |
| `GetWorldName(id)` | 全部界面统一世界名称 |
| `GetDocument(id)` | 通关文书；文书关闭时返回null |
| `GetPlayerProfile(id)` | 仅两条玩家档案描述和本日重点维度 |
| `GetPortraitKey(id)` | 当次申请对应的稳定立绘Key |
| `SubmitApplication(id, approve)` | 推荐的二选一审批入口 |
| `SubmitDecision(id, choice)` | 兼容显式操作入口；改派或扣留被拒绝且不改状态 |
| `EndDay(expectedDay)` | 唯一日结入口，返回精确累计的展示值、实际变化和记录 |
| `GetAvailableFeedback()/ConsumeFeedback(id)` | 到期未消费查询；实际播放后确认消费 |
| `GetProfile/GetNpc/PreviewRule` | 开发者检查，不能直接绑定普通玩家面板 |

日结回调先保存当天编号，重复回调仍传这个编号，不能每次读取最新天数再结算。先检查次日规则并准备生成，成功后才提交本日结算，避免半次结算。人物与当天申请保持在内存中，没有存档协议。

世界累计使用decimal账本，日终对“旧世界值＋全部变化”使用四舍五入，再限制0～100。默认除数5不会逐人取整；例如三个+0.2累计+0.6，50变51。用于边界测试的除数2下，50−0.5=49.5取50，50+0.5取51，明确不采用银行家舍入。

原NPCDailyManager的固定8人、TutorialManager的固定盖章对错及旧收容流程不会自动改变。队友需要将场景人数、按钮、日结和反馈绑定到新接口；本轮没有替队友修改场景或旧UI。

## 7 同步来源数据

项目保留 `Editor/SourceWorkbook.json` 原表快照和 `Editor/PlannerReply.json` 策划答复快照，均带SHA256。`Defaults.json`是当前配置基线，`.asset`是Unity实际读取的配置。

如需重建本轮基线：

```powershell
python Assets/GameData/Tools/apply_planner_reply.py "原V3表格完整路径.xlsx" "策划答复完整路径.docx"
```

此命令严格匹配本次文档结构和关键约定，覆盖默认资产、JSON基线及快照，但不改输入文件，也不改资产meta/GUID。**先提交或备份你的自定义默认配置与Sprite绑定**；自己的资产副本不受影响。策划规则进一步改变时，应先更新导入器，不能把它当任意文档自动导入工具。

旧 `import_v3.py` 现在只更新原表快照，不再把旧草案覆盖到当前可运行配置。平时调整自己的资产不会反向修改Excel、Word或JSON。

### 常见问题

**为什么运行能通过，正式检查仍报错？** 当前世界/信任是测试公式，人物和立绘为样本，反馈是事实占位；它们都需要完成正式交付确认。

**为什么没有调查和扣留？** 策划已移除调查；扣留缺完整后续流程，本轮按授权建议先不开放。

**为什么世界状态审批后不变？** 只记账，日结后统一改变。界面可以即时刷新实际值，不能提前应用影响。

**为什么信任到了0还继续？** 失败条件尚未确认，目前只记录触边；不会沿用旧版世界≤20的失败规则。

**为什么图片空白？** 默认只有占位Key；按原籍池配置Key并绑定Sprite。程序不会用随机其他图片掩盖缺失。

**修改参数后没效果？** 当前局使用快照，重新开局。多日模拟在有当前局时使用当前局配置快照，种子输入只影响新模拟。
